Wisp × Cursor 桥：使用说明

Wisp × Cursor bridge: usage

课题文件夹里交接；本仓库只是适配器。

Handoff lives in the topic folder; this repo is only the adapter.

这是什么

What this is

Cursor 负责会员模型与改文件；Wisp Science 负责科研技能与生物工具。 科学状态写在磁盘上的 wisp.handoff.v1（research/HANDOFF.md、 research/sessions/、.wisp/memory/）。 两侧聊天气泡不同步。

Cursor membership models stay in Cursor. Wisp Science workflows (skills and bio tools) run through the adapter. Scientific state lives on disk as wisp.handoff.v1 (research/HANDOFF.md, research/sessions/, .wisp/memory/). Chats do not sync.

打开哪里

Where to open

在 Cursor 里打开 Wisp 课题文件夹，不要打开本适配器仓库。 菜单：File → Open Folder，选课题根目录 （里面应有或将有 research/HANDOFF.md）。 适配器仓库只用于改桥、跑测试、同步技能。

Open the Wisp topic folder in Cursor, not this adapter repo. Use File → Open Folder and pick the topic root (it should contain, or will get, research/HANDOFF.md). Open the adapter only to change the bridge, run tests, or sync skills.

克隆后先跑安装检查

After clone: run the setup check

打开本适配器仓库时，代理应运行检查并提示你完成设置。也可自己跑： uv run --python 3.12 python -m tools.check_bridge_setup。 git 检测的是有没有做过 git init（是不是本地仓库）。 没有则提示你在此初始化，方便跟踪改动和回滚；若本意是用适配器，再 clone。 本地 git 只用于记录和回滚。适配器与课题靠文件区分 （INTEROP.md + gateway/ + tools/sync_wisp_skills.py），不用 git remote。 不要粘贴别人的个人 User Rules。

When you open this adapter clone, the agent should run the setup check and prompt you. You can also run uv run --python 3.12 python -m tools.check_bridge_setup. The git check only asks whether git init has already happened. If not, you are prompted to git init for local history and rollback, or to clone the adapter if that is what you meant. Local git is not for publishing a topic folder. Adapter vs topic is file-based (INTEROP.md + gateway/ + tools/sync_wisp_skills.py). Do not paste someone else’s personal User Rules.

不要在课题里跑 uv sync

Do not run uv sync in a science folder

不要在课题文件夹里执行 uv sync，也不要在那里添加 pyproject.toml。 uv sync --python 3.12 只属于本适配器仓库。

Do not run uv sync in a science folder, and do not add pyproject.toml there. uv sync --python 3.12 belongs only in this adapter repo.

路径触发（最高优先，无需口令）

Path trigger (no passphrase)

路径触发是可选的。设置环境变量 WISP_TOPICS_ROOT，或在 .wisp/topics-root.local 写一行绝对路径后，该根目录下的 工作区会自动视为 WS 课题。永远不要把本适配器仓库 （wisp-cursor-bridge）当成课题文件夹。

Path trigger is optional. Set env WISP_TOPICS_ROOT or one path line in .wisp/topics-root.local; workspaces under that root auto-qualify as WS topics. Never treat this adapter repo (wisp-cursor-bridge) as a science folder.

口令触发（课题根以外也有效）

Spoken triggers (any folder)

文件夹不在课题根下时，用口令。说完口令后若已写明要做的事，就做那件事； 否则做该课题 HANDOFF 的 next。

If the folder is not under the topics root, say a passphrase. After wiring, do the rest of the sentence if you already specified work; otherwise do that topic’s HANDOFF next.

  • 继续 / 接管 / 接上 + WS / Wisp + 任务 / 桥（如「继续这个WS任务」「接上Wisp桥」）
  • 这是WS任务，帮我 / 请帮我 / 我要…（Wisp 任务同理）
  • 读HANDOFF继续 · 读 HANDOFF 继续 · 读交接继续
  • 英文：continue the WS task、wire the wisp bridge、take over this WS task、use the wisp-cursor bridge here
  • Chinese: 继续 / 接管 / 接上 + WS / Wisp + 任务 / 桥 (e.g. 继续这个WS任务, 接上Wisp桥)
  • 这是WS任务，帮我 / 请帮我 / 我要… (same with Wisp)
  • 读HANDOFF继续 · 读 HANDOFF 继续 · 读交接继续
  • English: continue the WS task, wire the wisp bridge, take over this WS task, use the wisp-cursor bridge here

安装 overlay

Install overlay

若课题里还没有 .cursor/mcp.json（或不含 wisp-bio）， 在适配器仓库用 Python 3.12 跑下面命令。已接过桥则不要重复同步。

If the topic folder has no .cursor/mcp.json (or it lacks wisp-bio), run this from the adapter with Python 3.12. Do not re-run sync if the overlay is already present. 

uv run --directory <adapter-repo> --python 3.12 python -m tools.sync_wisp_skills --science <topic-folder>

--user-mcp 是可选项：仅当本机还没有用户级 MCP （~/.cursor/mcp.json）时才加。已有用户 MCP 时不要当作默认必加参数。 第一次写入 overlay 后，可能需要 Reload Window， 并在 Settings → Tools & MCP 批准 wisp-bio / wisp-history / figure-library。

--user-mcp is optional: add it only if this machine has no user-level MCP yet (~/.cursor/mcp.json). Do not treat it as a required default when user MCP already exists. After the first overlay, you may need Reload Window and to approve wisp-bio / wisp-history / figure-library in Settings → Tools & MCP.

回到 Wisp 继续

Continue in Wisp

在 Wisp 打开同一个课题文件夹，说「读 HANDOFF 继续」。 内核变量不会带过去；脚本必须能从文件重跑。

Open the same folder in Wisp and say 读 HANDOFF 继续. Kernel variables do not carry over; scripts must be rerunnable from files.

User Rules（任意文件夹都能触发口令）

User Rules (passphrases in any folder)

Cursor → Settings → Rules → User。加一段短规则，指向 ~/.cursor/skills/ws-continue/SKILL.md （技能名 ws-continue）。 内容写清：课题根路径自动接桥；口令在其他目录也有效； 不要把适配器仓库当成课题。

Cursor → Settings → Rules → User. Add a short block that points at ~/.cursor/skills/ws-continue/SKILL.md (skill name ws-continue). State that a workspace under the topics root auto-wires, spoken passphrases still work elsewhere, and the adapter repo is never a science folder.

协议全文见仓库根目录 INTEROP.md （wisp.handoff.v1）。

The on-disk contract is INTEROP.md (wisp.handoff.v1) at the repo root.

适配器仓库文档。语言选择保存在本机 localStorage（wisp-bridge-lang）。 Adapter-repo documentation. Language is stored in localStorage (wisp-bridge-lang).
